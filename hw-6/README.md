### Перечень вопросов, которые также могут задать 

<br> 

1. В каких сценариях могут использоваться очереди сообщений? <br>
   - Асинхронная обработка заданий (например, отправка email).
   - Балансировка нагрузки между несколькими серверами.
   - Обмен сообщениями между микросервисами.
   - Гарантированная доставка сообщений даже при сбоях.<br><br>
2. Что такое Apache Kafka? В каких случаях он эффективней RabbitMQ, а в каких наоборот? <br>
   - Kafka - оптимизирована для высокой пропускной способности и хранения больших объемов данных. Лучше подходит для потоковых данных и аналитики в реальном времени.
   - RabbitMQ - инструмент больше ориентирован на маршрутизацию сообщений и гибкость. Эффективнее для сложных топологий обмена сообщениями и поддержки различных протоколов.<br><br>
3. Что такое RabbitMQ? Для чего используется? <br>
   - Используется для обмена сообщениями между приложениями.
   - Поддерживает различные протоколы (AMQP, MQTT, STOMP).
   - Подходит для маршрутизации, буферизации и гарантированной доставки сообщений.<br><br>
4. Как обеспечить надежность и эффективность системы при использовании RabbitMQ? <br>
   - Настройка кластеров для отказоустойчивости.
   - Использование persistent queues для сохранения сообщений на диске.
   - Оптимизация настроек производительности (prefetch count, message acknowledgment).<br><br>
5. Чем отличаются схемы независимых подписчиков и конкурирующих подписчиков? <br>
   Возможен ли смешанный вариант?
   - Независимые подписчики, где каждый потребитель получает копию сообщения.
   - Конкурирующие подписчики, когда сообщение доставляется только одному потребителю.
   - Смешанные варианты возможны через использование разных типов обменников (Exchange).<br><br>
6. Для чего используется Exchange? Как Exchange принимает решение, что делать с
   сообщением? <br>
   - Назначение - определяет, куда отправить сообщение (в какую очередь или несколько очередей).
   - Принятие решения - зависит от типа exchange (direct, fanout, topic, headers).
